# تقرير مراجعة وخريطة موقع مركز الإمام الحجة – باريس

تاريخ المراجعة: 13 سبتمبر 2026. النسخة: RC3، امتداد RC2. الفرع الوحيد: `design-refinement-2026`.

## الحكم التنفيذي

النسخة تحتوي واجهة المؤسسة وأدوات الإدارة اليومية وكود المنصة الأكاديمية والرقمية. اجتازت فحوص الكود والبناء والروابط الموضحة أدناه. **ليست جاهزية تشغيلية كاملة مثبتة للإطلاق العام بعد**: لم تُجرَّب عمليات المدير بحساب فعلي مع التخزين، ولم تُنشر النسخة على Vercel، ولم تكتمل معاينة مرئية لها على الهاتف والحاسوب.

وجود صفحة أو زر لا يثبت أن خدمة Google المرتبطة به مفعّلة. هذا التقرير يفرّق بين اكتمال الكود وتشغيل الخدمات. المراجعة تخص النسخة المحلية المبنية على الفرع المحدد؛ ليست تقييمًا للموقع الأزرق القديم المنشور.

| Git | مراجعة الفرق وفحص المسافات قبل الحفظ المحلي؛ لم يُعدّل main ولم يُرفع شيء إلى GitHub في هذه المراجعة |

| التشغيل الحقيقي | Google OAuth، الرفع، النشر، التسليم الخاص وعمليات الطالب والأستاذ تحتاج اختبارًا متصلًا. اختبارات Apps Script تستخدم خدمات Google محاكية |

إصلاح PostCSS يعالج تنبيهات مكتبة تابعة ولا يساوي اختبار اختراق شاملًا. مرجع النسخة المصححة: [GitHub Advisory](https://github.com/advisories/GHSA-fxqj-rqcc-2cmp). لم يُستخدم `npm audit fix --force` ولم تُجر ترقية إلى Next.js 16.

## نتيجة فحص GitHub وVercel وDrive

- [مستودع المشروع والفرع](https://github.com/espoparis/espoparis/tree/design-refinement-2026) متاح للقراءة. مقارنة الفرع بالـSHA `75f93278b7f2b8157307848348d2267760c7d6e7` أعادت `identical`: تعديلاتنا المحلية لم تصل إلى الفرع البعيد.
- المستودع عام وغير مؤرشف، وفرعه الافتراضي main. بيانات صلاحيات حساب GitHub تُظهر push وadmin؛ لكن محاولة الكتابة السابقة عبر التكامل رُفضت بـ403: `Resource not accessible by integration`. صلاحية الحساب وصلاحية تطبيق التكامل أمران مختلفان. لم نكرر طلب كتابة أثناء الفحص ولم نفترض زوال الرفض.
- اتصال Vercel موجود، لكن استعلام الفرق أعاد قائمة فارغة واستعلام المشاريع فشل. لم نحدد مشروع الاستضافة أو متغيراته، ولم ننشر أي نسخة. ربط التطبيق وحده لا ينقل ملفات المشروع.
- تم التحقق من هوية Drive: `digital@espoparis.com`. مجلد فهرس المنصة المتوقع موجود، لكن البحث داخله لم يعرض ملفات، والبحث عن CMS لم يعرض تطابقات. هذا لا يثبت غياب البيانات في أماكن أخرى، لكنه لا يسمح باعتبار التفعيل منتهيًا.
- لم يرصد الفحص النصي تواقيع مفاتيح خاصة أو رموز GitHub أو مفاتيح Google ضمن الملفات المتتبعة؛ هذا ليس ضمانًا مطلقًا لغياب كل نوع من الأسرار. لا تتضمن الحزمة ملفات بيئة فعلية أو node_modules أو ملفات بناء. لم تتغير ملكية ملفات Drive أو إعدادات مشاركتها.

## ماذا تستطيع تعديله بنفسك؟

| ما تريد فعله | من أين؟ | التفاصيل |
|---|---|---|
| إعلان نشاط مع بوستر ووصف | إدارة المحتوى | إنشاء، رفع صورة، حفظ مسودة، مراجعة ثم نشر بواسطة المدير |
| إزالة إعلان انتهى | إدارة المحتوى | إخفاء قابل للاستعادة أو تحديد نهاية العرض؛ يوجد حذف نهائي للسجل بعد تأكيد |
| تغيير آية أو حكمة | إدارة المحتوى | النص والمصدر والترجمات والتوقيت والأولوية، ثم اعتماد المدير |
| زيادة تعريف الشيخ الخطيب | سير الأساتذة | اختيار الأستاذ واللغة، تعديل السيرة ثم اعتمادها؛ تحرير كل ترجمة مستقل |
| إضافة كتاب | إدارة المكتبة | بيانات الكتاب وPDF وغلاف اختياري وحقوق الوصول، ثم المراجعة والنشر |
| إزالة كتاب من العرض | إدارة المكتبة | أرشفة الكتاب؛ يبقى الملف في Drive ويمكن استعادته |
| تغيير نص عام أو هيكل صفحة | ملفات المشروع | ليست لوحة الإدارة محررًا شاملًا لكل صفحات الموقع |
| إضافة أستاذ جديد خارج القائمة | تطوير المصدر | المحرر الحالي يحدّث الأعضاء السبعة الموجودين |

الصورة تُجهّز في المتصفح بصيغة JPEG حتى 1 MB بعد المعالجة. الصيغ المقبولة JPG وPNG وWebP؛ لا SVG أو GIF، وقد تزول شفافية PNG. PDF مباشر حتى 3 MB؛ الكتب الأكبر تُرفع إلى مجلد الكتب المعتمد في Drive ثم يُلصق رابطها في محرر الكتاب. الأرشفة وحذف سجل الإعلان لا يحذفان الملفات الأصلية من Drive تلقائيًا.

النص اليومي ليس مولدًا آليًا ولا شريطًا متحركًا: يظهر نص معتمد ضمن موعده. الأولوية الأعلى تفوز؛ تتناوب النصوص المتساوية يوميًا حسب UTC. الترجمات والسير والمصادر مسؤولية المؤسسة، ولا يُخترع منها شيء.

صفحة الدعم موجودة ولكنها توجه للتواصل، ولا تتضمن Checkout أو معالجة بطاقة أو إيصالًا ضريبيًا آليًا. لم يُثبت هذا الفحص أهلية قانونية أو ضريبية لجمع التبرعات. خيار الوصول المدفوع في المكتبة يستخدم حقوق الوصول الموجودة، ولا ينشئ نظام دفع جديدًا.

## كيف ننقل النسخة؟ وهل نحذف القديم؟

**لا نحذف المستودع، ولا main، ولا نفرغ مجلداته.** نحدّث الملفات المقصودة على `design-refinement-2026` مع الاحتفاظ بسجل Git والنسخة المنشورة السابقة للرجوع إليها.

المسار المفضل أن تُصلح صلاحية GitHub integration للكتابة على هذا المستودع، ثم تُرفع التغييرات المحددة مباشرة إلى الفرع. الرفض السابق تقني في التكامل، وليس طلبًا منك لإعادة البرمجة أو تشغيل أوامر على لابتوب.

البديل إذا بقيت صلاحية التكامل مرفوضة هو رفع الملفات عبر واجهة GitHub من جهاز يدعم فك ZIP واختيار الملفات:

1. نزّل حزمة **RC3 Changed Files** وفك ضغطها. حزمة Source هي نسخة كاملة للمراجعة أو الاستعادة.
2. افتح المستودع واختر `design-refinement-2026` صراحة، ثم تأكد أنك في جذر المشروع.
3. اختر Add file ثم Upload files، وارفع الملفات المستخرجة مع حفظ مساراتها. ملف ZIP نفسه لا يصبح كود الموقع، ولا ترفع مجلدًا إضافيًا يحيط بكل المشروع.
4. راجع الملفات التي ستُستبدل ثم احفظ Commit على الفرع نفسه. إن احتاجت الواجهة دفعات، أكملها كلها قبل اعتماد أي نشر.
5. قارن النتيجة بملف manifest المرفق، وتأكد من عدم حذف ملفات غير موجودة في حزمة التغييرات. الحزمة الحالية إضافات وتعديلات فقط؛ لا تتطلب حذف ملفات المصدر القديمة.

إجراءات الرفع قد تختلف حسب واجهة الجهاز. لا ترفع `.env` أو مفاتيح أو بيانات طلاب. التعليمات لا تعني أن الرفع قد تم؛ وقت التقرير لا تزال التغييرات محلية.

## ما يلزم قبل الإطلاق الفعلي؟

1. وصول صحيح إلى مشروع Vercel الذي سيستضيف هذه النسخة، ثم رفع الفرع المراجع إلى GitHub.
2. تحديد قواعد البيانات ومشروعي Apps Script الحاليين قبل إنشاء أي شيء؛ الحفاظ على البيانات والمفاتيح القديمة وتحديث الجسرين المنفصلين.
3. ضبط أسرار الاتصال وOAuth في إعدادات الاستضافة الخاصة وربط عنوان معاينة صحيح.
4. نشر Preview من `design-refinement-2026`، ثم تسجيل دخول مدير مخوّل وتجربة نشاط وصورة وكتاب وسيرة ونص يومي وإخفائها بعد الاختبار.
