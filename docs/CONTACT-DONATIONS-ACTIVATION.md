# Contact inbox and donation activation

The contact form now stores validated enquiries in `CMS Contact Inbox` through the signed CMS bridge. The master administrator can read the most recent 200 at `/en/admin/content/inbox` (or a localized route). An email notification is attempted when Resend is configured. If CMS is unavailable and email is configured, contact falls back to email; such messages do not appear in the admin inbox. If neither service is configured, the form reports an error. Inbox access is restricted to the master administrator. No visitor message is included in the public CMS snapshot.

Deploy the updated `integrations/google-apps-script/cms.gs` in the existing institution-owned CMS Apps Script project. Keep its existing Script Properties (`CMS_API_SECRET`, `CMS_SPREADSHEET_ID`, and media folder) and deployment access. Run `provisionCmsWorkspace()` to create the new `CMS Contact Inbox` and `CMS Settings` sheets. Deploy a new version of the CMS Web App and confirm that Vercel has `CMS_API_URL` and `CMS_API_SECRET` set for the intended environment. Never copy the secret into GitHub. Test a benign enquiry in each locale and verify the admin inbox and optional email notification. This requires an actual live test; a local build does not prove delivery.

Online donations remain hidden until the master administrator enters a PayPal *hosted donation button* URL in `/en/admin/settings/donations` and checks enable. The accepted format is `https://www.paypal.com/donate/?hosted_button_id=...`. The public support page retains its existing contact options. Use the association's verified PayPal account; confirm its legal wording and receipt policy with the association. This configuration does not store bank credentials, process payments, or issue tax receipts.

Paid courses remain inaccessible without an existing entitlement. The current `paid` access level and restricted delivery can check entitlements, but no live PayPal Orders integration, webhook verification, purchase ledger, or admin course bundle pricing is connected. Do not advertise automatic paid access until the association provides a PayPal business account's API credentials through Vercel environment variables and the checkout, capture, refund, and entitlement flow passes end-to-end testing. Do not collect card or bank details through the CMS.

The profile editor at `/en/admin/content/profiles` can edit existing scholars or create a new profile with a stable lowercase slug, biography, role, and image. A master administrator approves each language version separately before it appears automatically in the faculty directory and detail route. The historical scholars' fallback copy still lives in the locale message files, so editing a fallback through the CMS creates an approved override. Verify a biography with its subject before publishing it.
