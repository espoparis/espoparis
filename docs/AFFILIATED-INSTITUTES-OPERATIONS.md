# Affiliated institutes: publication and maintenance

The public network in `messages/{en,fr,ar,fa}.json` includes the institution's established descriptions and the four Nigeria entries supplied by the center. Names, addresses and telephone numbers in those entries are editorial source data. The malformed Nigeria email provided without an `@` is deliberately unpublished pending confirmation. New institutes can be added through the CMS by language.

The `/[locale]/admin/content/institutes` route requires content editing permission. An editor can prepare a draft; only the master administrator can approve an institute for public display, alter an approved institute, or remove it. Name, country, description paragraphs and display order are language-specific. Publishing in one language does not generate translations in the others. The institutional pages and global presence page read approved records from the CMS, then display them alongside the established static network. To revise an established static entry, edit its translations and redeploy the site; later admin additions are edited within the CMS.

The Apps Script CMS bridge must be redeployed from the updated `integrations/google-apps-script/cms.gs` for institute operations. `CMS Institutes` is created on first snapshot via the existing schema helper. Until that deployment, the established network is visible but the new admin operation returns an unsupported action and should not be represented as live. A successful website build by itself does not update an Apps Script deployment. No payment settings or entitlement behavior are changed here.
